Date: 2026-08-13. Author: repo bootstrap session (Claude Code + Aditya).

## 1. Machine / environment
Windows 11 Home, Ryzen 7 5700 (8C/16T), 16 GB RAM, **RTX 4060 Ti 8 GB**, driver
610.62 (CUDA 13.3), WSL2 Ubuntu-24.04 with working GPU passthrough. Full details:

## 3. A3 model status
- Official repo `AgibotTech/A3-A3U-robot-model` pinned @ `589f508` (Mulan PSL v2 —
  permissive). Four variants; **a3_ultra_t2d5** chosen for locomotion (T3.0 adds
  dexterous hands only).
- **31 actuated DOF** (12 legs, 3 waist, 14 arms, 2 head), 60.18 kg, `pelvis_link`
  root, 13 contact spheres per foot, IMU sites in pelvis+torso, full MJCF sensor
  suite. Joint naming is **identical convention to Unitree G1 29-DOF** — verified
  string-for-string — which made the Holosoma port config-only.
- Canonical manifest: `configs/robots/a3_ultra.yaml` (official vs assumed values
  explicitly separated; PD gains/armature/default pose are assumptions).
- Training asset: `assets/a3_ultra/holosoma/a3_ultra_29dof.{xml,urdf}` generated by
  `scripts/convert/make_holosoma_asset.py` (head welded → 29 controlled DOF, foot
  contact-point bodies added, mass preserved to 2 g; 26 per-link mesh collisions
  replaced by 10 AABB-fitted boxes — the official mesh collisions overflow
  MJWarp's per-env constraint budget; 11 zero-mass decorative links stamped with
  tiny inertials so URDF importers don't invent ~19 kg from mesh volumes).
- **MuJoCo validation: 12/12 PASS** (`scripts/diagnostics/check_mujoco_model.py`),
  incl. stiff-PD settle, foot contacts (L 294 N / R 297 N vs 590 N weight),
  penetration < 0.1 mm, 0.15 m/s push recovery; settle video in
  `results/diagnostics/`. Physics note: passive PD standing needs ankle stiffness >
  m·g·h ≈ 530 Nm/rad, so diagnostics use a documented stiff "hold mode" while RL
  configs keep realistic gains.

## 5-7. Baseline comparison, selection, and why
Decision matrix with weighted scoring: `docs/baseline_selection.md`.
- **Primary: Holosoma + FastSAC** (4.35/5) — the training recipe already contains
  our stability ingredients (rough terrain + pushes + heavy DR + action-rate
  curriculum), hardware-validated on two humanoids, Apache-2.0, actively
  maintained, native MuJoCo sim-to-sim, and its MJWarp backend is the only modern
  GPU training stack that runs on this machine (WSL2).
- **Fallback: Isaac Lab 2.3 + RSL-RL PPO** (3.75) — native Windows, aligns with the
  project's Isaac Lab ecosystem and Tomasz's terrain work.
- **Reference: AGIBOT X1 conventions + Humanoid-Gym sim2sim methodology** — legacy
  Isaac Gym stacks, X1 has **no license** (no code reuse; ideas documented).
- **Rejected: cross-embodiment checkpoints** — nothing public/usable as of Aug 2026.
- **Earmarked for perception phase: InstinctLab** (Isaac Lab extension, CC BY-NC).
- The user's initial hypothesis was confirmed on all three counts.

## 8. What actually runs (verified this session)

2. Holosoma E00 (upstream G1 FastSAC, MJWarp, 512 envs): runs on GPU (WarpBackend +
   CUDA graph), VRAM ~3.8 GB — but see §11 wall-clock caveat.
3. A3 Ultra FastSAC training (`exp:a3-ultra-fast-sac`): presets registered and

   upstream run on this machine, see §11).
4. Stability suite on the PD-stand baseline: full metric pipeline incl. procedural
   terrain injection (11/12 scenarios survived; rough-terrain fall expected for a
   non-stepping baseline).
5. Isaac Lab headless boot on this GPU (below min spec): boots; A3 URDF validation
   via `scripts/diagnostics/check_isaac_a3.py` (see §10-addendum).
